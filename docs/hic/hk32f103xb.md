# HK32F103XB

HK32F103XB from Hangshun mostly similar to STM32F103CBT6, but with a few differences. Also, an ungraded version HK32F103CBT6A exist, which is reported to have more compatibility with STM32F103CBT6, but it should be considered as separate device with different capabilities and SDK.

## Porting

Porting was performed using stm32f103xb port as a reference, but with original SDK from Hangshun. Also, some code was modified (USB and UART) to mitigate compatibility issues.

## Configuration

- **HIC ID**: `0x97969950` (HK32F103XB)
- **OS_CLOCK**: 48 MHz (HSI) or 72 MHz (HSE)
- **Flash**: 128 KB (0x08000000 + 48KB bootloader)
- **RAM**: 20 KB (0x20000000)

## Hardware Notes

Hardware is fully compatible with stm32f103xb port:

- The nRESET pin (PB0) is configured as *Input with Pull-Up (IPU)* for reset button detection
- USB control pin (PA15) for D+ pullup
- Main LED (PA9) in two modes (VDD and GND) for RUNNING, HID, CDC and MSC activity indication
- Extra LED (PB6) for USB connection indication
- Output SWD on PB13 (SWCLK), PB14 (SWDIO OUT) and PB12 (SWDIO IN).


## Known Issues and Limitations

### USB BULK Hardware Issue

The HK32F103XB USB peripheral has a hardware quirk or bug that affects BULK endpoint data transmission. This issue manifests when receiving multiple back-to-back OUT packets from the USB host.

According to the HK32F103XB User Manual (Section 18.3.2.5), when a BULK OUT packet is received correctly:
1. Hardware sets STAT_RX to NAK (0b10)
2. Hardware sets CTR_RX flag to trigger interrupt
3. Software should process the data and set STAT_RX back to VALID (0b11) to accept the next packet

But what actually observed, that on BULK OUT data reception, the device immediately ACK data transfer, despite EP status was correctly set to NAK (which was checked). Here is example tract when sending 20 bytes to CDC endpoint (16 bytes + 14 bytes split into two subsequent packets):

```
Time[s]       Direction  PID   Data
19804	1.242160433	host	3.4	USBLL	19	DATA1
19805	1.242174350	3.4	host	USBLL	1	ACK
19806	1.242176516	host	3.4	USBLL	3	IN
19807	1.242179850	3.4	host	USBLL	1	NAK
19808	1.242182100	host	3.4	USBLL	3	OUT
19809	1.242185350	host	3.4	USBLL	17	DATA0
19810	1.242198016	3.4	host	USBLL	1	ACK   # <-- NAK expected here, but ACK responded
19811	1.242200183	host	3.4	USBLL	3	IN
19812	1.242203433	3.4	host	USBLL	1	NAK
19813	1.242206766	host	3.4	USBLL	3	IN
```

The result:

1. CDC works well on data reception. On transmission, works only for small packets (<= 16 bytes). On input packet burst data will be lost.
2. MSC doesn't work.

### Target Adapter Speed

Default adapter speed set to 1MHz, since on test setup 5MHz was sometimes unreliable.
